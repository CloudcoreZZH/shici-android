# 0.4.0：墨白书页、义项证据与流畅度

## 设计落地

采用用户选定的 A 方案：纸白 `#F7F3EA`、墨黑 `#232524`、朱红 `#AF493A`，英语词头和数字使用系统衬线字体，中文保持系统字体及字号缩放。没有下载字体、贴图、模型或新依赖。

首页采用并列任务数字、细线和七天复习日历；查词、词书和复习清单采用平面行；答题页左对齐词头，四档评分用柔和背景。按钮最小 56 dp，圆角 6 dp，深色采用暖黑背景。概念图里的示例数量、日期、释义排序和引语不是产品数据；应用没有使用未经核验的名人署名。

横屏答题采用词头与释义双栏、四档评分单行；竖屏评分两行。系统字号 1.6 倍通过可见性测试。系统移除动画设置仍由 Compose 的动画时长缩放处理。

## 针对掉帧的修改

- 长词条中文释义、维基补充释义、学习展开释义变为带稳定键和内容类型的懒加载项目。250 条释义测试验证末尾未提前创建、滚动后可到达，底部加词操作仍可见。
- 显示答案前后保留相同评分区尺寸；回归测试确认词头位置不变。揭晓不再同时创建两个大内容树并改变整页高度。
- 换词动画仅携带当前词页面数据；揭晓透明度在绘制阶段读取。页面采用 70 ms 淡出、随后 180 ms 淡入，减少整页重叠绘制。预测性返回复用圆角形状，避免逐帧创建形状。
- 复习队列排序每个不可变状态只计算一次；词书筛选、学习间隔和日历结果按输入缓存。移除每条查词结果额外查询旧 `exam_senses` 空表的开销。
- 使用 Compose 1.9 的 `Modifier.preferredFrameRate(120f)` 参与原生绘制投票，取代一次性写入宿主 View 的刷新率请求。没有固定刷新定时器、强制显示模式或禁用系统自适应刷新。

这些是明确的开销削减，**不是已经测得小米 13 Pro 达到稳定 120 FPS 的结论**。本次项目专用 ADB 端口未检测到手机，没有生成真机帧率提升百分比。Android 16 测试环境截图也不代替手机性能测量。

## 本机记录方法

1. 安装同签名新版，进入「我的 → 流畅度记录 → 开始记录 60 秒」。
2. 返回之前卡顿的页面，重复滚动长词条、切换页面、显示答案和评分。
3. 60 秒后自动停止，或返回「我的」手动停止；切到后台会停止。
4. 查看 / 复制报告，附上最明显的操作；记录前后对比时保持系统高刷、省电模式和设备温度尽量一致。

报告包含应用绘制耗时 P95、最慢帧、超过每帧系统截止时间的比例、排除首绘数和统计回调遗漏数。截止时间取自每帧的 `FrameMetrics.DEADLINE`，不硬编码所有帧都只有 8.33 ms。屏幕 Hz 是开始时的模式信息，不当作实测 FPS；回调遗漏不当作掉帧数；没有截止时间的帧不伪造为成功帧。

记录默认关闭，最多 60 秒 / 20000 帧，仅使用有限内存；没有逐帧界面状态更新、悬浮层、上传或文件写入。排序汇总在独立工作线程进行，关闭后释放监听和线程。

官方依据：[Compose 自适应刷新率](https://developer.android.com/develop/ui/views/animations/adaptive-refresh-rate)、[FrameMetrics](https://developer.android.com/reference/android/view/FrameMetrics)、[Compose 性能建议](https://developer.android.com/develop/ui/compose/performance/bestpractices)。

## 义项频率边界

遵照用户最新决定，仅真实逐义项统计参加频率排序，缺失显示「未统计」。旧版的 120 词编辑顺序不再作为默认学习顺序；原创例句继续标注「非真题」。全部原词典释义保留。

当前发布包经过核验的义项频率数据覆盖 **0 词**。实现了数据校验、降序排序、未知值置后、统计范围和逐次出处查看，但**没有完成真实统计数据的填充，也没有完成 2027 英语（一）全量义项频率**。不是把空数据接口称为已经完成的数据工程。

具体数据结构、免费候选资料核查和接入门槛见 [考研义项频率数据规范](考研义项频率数据规范.md)。
